# Plano: Aba "Metas" — Análise de Desempenho e Estado Mental

## Visão Geral

Criar uma nova aba `/goals` que funciona como um **painel analítico pessoal**, indo além de definir metas — analisando dados reais do usuário para mostrar consistência, nível de motivação, estado mental de estudo, e insights acionáveis.

---

## 1. Modelo de Dados

### Nova tabela `goals` no SQLite

```
goals
├── id (PK)
├── user_id (FK → users)
├── profile_id (FK → profiles)
├── title (TEXT NOT NULL)
├── description (TEXT)
├── goal_type (TEXT NOT NULL) -- 'study_time' | 'streak' | 'accuracy' | 'volume' | 'completion' | 'custom'
├── target_value (REAL NOT NULL)
├── current_value (REAL DEFAULT 0)
├── unit (TEXT) -- 'minutes' | 'days' | 'percent' | 'count'
├── subject_id (FK → subjects, nullable) -- meta pode ser por matéria
├── topic_id (FK → topics, nullable) -- ou por tópico específico
├── period (TEXT DEFAULT 'weekly') -- 'daily' | 'weekly' | 'monthly' | 'total'
├── start_date (TEXT NOT NULL)
├── end_date (TEXT)
├── status (TEXT DEFAULT 'active') -- 'active' | 'completed' | 'expired' | 'abandoned'
├── created_at (TEXT)
├── updated_at (TEXT)
```

### Índices
- `(user_id, profile_id, status)` — queries de metas ativas
- `(user_id, profile_id, goal_type)` — agrupamento por tipo

## 3. Backend — Endpoint de Analytics

### Novo endpoint: `GET /api/goals/analytics`

Este endpoint **não consulta uma tabela** — ele computa tudo a partir dos dados existentes (`study_sessions`, `question_history`, `review_attempts`, `review_schedules`, `completed_items`).

```
GET /api/goals/analytics
Header: X-Profile-Id: <id>

Response: GoalsAnalytics (computado em runtime)
```

#### Lógica de Cálculo (Python)

**Consistency:**
- `currentStreak`: caminhar para trás a partir de hoje contando dias com sessões
- `longestStreak`: varredura completa do histórico
- `averageMinutesPerDay`: `sum(duração) / 30` últimos dias
- `consistencyScore`: fórmula `min(100, (dias_estudados_30d / 30) * 100 * (1 + streak_bonus))`
- `weeklyPattern`: agrupar por dia da semana
- `monthlyTrend`: comparar minutos das últimas 2 semanas vs 2 anteriores

**Motivation:**
- `overallScore`: média ponderada de frequência(30%), duração(20%), dificuldade(25%), melhoria(25%)
- `riskLevel`: se `lastActivityDays > 5` → high, `> 3` → medium, senão low
- `trend`: comparar métricas das últimas 2 semanas vs 2 anteriores

**Mental State:**
- `blankAnswerRate`: `blankCount / (correct + wrong + blank)` do question_history
- `difficultyTrend`: média de `difficulty` das sessões recentes
- `reviewAvoidance`: `pending_reviews / total_reviews` do review_schedules
- `energyPattern`: analisar `started_at` das sessões para agrupar por período do dia
- `burnoutRisk`: combinação de queda de duração + queda de frequência + aumento de respostas em branco
- `overallLabel`: mapear score → label em português
- `recommendation`: gerar recomendação baseada nos indicadores

**Habits:**
- `preferredTime`: moda do horário de início das sessões
- `favoriteMode`: modo mais usado
- `mostStudiedSubject`: subject com mais minutos
- `weekendVsWeekday`: média de minutos em dias de semana vs fim de semana

**Weekly Report:**
- Comparação com semana anterior usando diffs

## 8. Decisões de Design

| Decisão | Escolha | Motivo |
|---|---|---|
| Analytics computed no backend? | Sim | Mantém frontend leve, lógica reutilizável |
| Cache de analytics? | Sim, no store Zustand | Evita recomputação a cada render |
| Meta pode ser por subject ou topic? | Ambos (opcionais) | Flexibilidade — meta global, por matéria, ou por tópico |
| Período da meta | daily/weekly/monthly/total | Cobrir diferentes cadências |
| Fórmula de burnout | Composto: duração↓ + frequência↓ + branco↑ | Sinal robusto baseado em múltiplos vetores |
| Recomendação textual? | Sim, gerada no backend | Valor percebido pelo usuário |
