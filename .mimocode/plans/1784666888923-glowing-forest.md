# Sistema de Revisão Espaçada — Plano de Implementação

## Visão Geral

Implementar um sistema de revisão espaçada adaptativa com dois modos (automático e manual), integrado ao Timer, sessões manuais, calendário e uma página de revisões funcional.

## Lógica de Negócio

### Modo Automático (baseado no desempenho)

| Último resultado | Nº de revisões | Intervalos |
|---|---|---|
| > 90% | 0 (reforço opcional em 7d) | — |
| 70–90% | 1 | 3 dias |
| 50–70% | 2 | 1 dia, 7 dias |
| < 50% | 3 | 1 dia, 3 dias, 7 dias |

### Comportamento Adaptativo

Após cada revisão, o sistema recalcula com base no ÚLTIMO resultado:
- **Melhorou de faixa** → reduz revisões restantes
- **Manteve na faixa** → continua o plano
- **Piorou** → adiciona revisões ou encurta intervalos

### Modo Manual

Usuário escolhe:
- Quantas revisões (1–5)
- Intervalos em dias para cada uma

## Fluxo de Dados

```
Timer/Sessão Manual → Pergunta modo de revisão
  → Modo Automático: accuracy → getAutoReviewPlan() → cria N ReviewSchedules
  → Modo Manual: user config → cria N ReviewSchedules com intervalos definidos

Revisão Pendente aparece no Calendário e na Página de Revisões

Usuário inicia revisão → registra acertos/total
  → Salva ReviewAttempt
  → Chama recalculateAfterReview()
    → Se melhorou: remove reviews pendentes extras
    → Se piorou: adiciona reviews extras
    → Se todas completadas com >70%: tópico considerado dominado
```
